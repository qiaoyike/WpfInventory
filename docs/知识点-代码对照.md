## 2. 分层架构与依赖方向

**概念**：表现层只依赖应用层，应用层只依赖领域层，基础设施层实现领域层/应用层定义的接口。上层不知道具体数据库和 UI 细节，这是“依赖倒置 + 分层架构”的核心。

**项目对照**：

- 实体和仓储接口在 `src/WpfInventory.Domain`，例如 `IRepository<TEntity>`。
- 数据库实现 `Repository<TEntity>` 在 `src/WpfInventory.Infrastructure`。
- 应用服务接口在 `src/WpfInventory.Application/Abstractions/Services`，实现也在应用层。
- 依赖方向是“向里依赖”，类似洋葱架构的雏形。

**面试常问**：

- 为什么要分层？各层分别放什么？
  - 分层让职责单一、依赖方向清晰，便于替换实现、维护和测试。表现层管交互，应用层管业务用例编排，领域层放实体/规则/接口，基础设施层提供数据库、文件等实现。
- Domain 层为什么不能引用 EF Core？
  - Domain 是核心业务，应保持稳定、不依赖具体技术。引用 EF Core 会把它和数据库实现耦合，换库、测试、演进都会变困难。EF Core 属于基础设施层。
- 依赖倒置原则（DIP）和依赖注入（DI）有什么区别？
  - DIP 是设计原则：高层依赖抽象，不依赖具体实现。DI 是实现该原则的手段：由容器把具体实现注入进来。

## 3. C# / .NET 基础知识

### 3.1 继承与抽象类

**概念**：把多个实体共有的字段抽到基类，子类自动拥有这些字段；基类用 `abstract` 表示不能直接实例化。

**项目对照**：`src/WpfInventory.Domain/Entities/BaseEntity.cs`

```csharp
public abstract class BaseEntity
{
    public int Id { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? UpdatedAt { get; set; }
}
```

`Product`、`Category`、`User` 等都继承 `BaseEntity`。

**面试常问**：

- 抽象类和接口有什么区别？
  - 抽象类是“is-a”，可以包含字段、构造函数和已实现成员，单继承；接口只定义契约，不保存状态，可多实现。两者都能实现多态。
- `virtual`、`override`、`abstract` 分别怎么用？
  - `abstract` 没有实现，派生类必须重写；`virtual` 有默认实现，可被重写；`override` 在派生类中重写基类的 virtual/abstract 成员。
- 什么时候用继承，什么时候用组合？
  - 继承表达“是”的关系但耦合强；组合表达“有”的关系，更灵活。能复用行为、不强调类型层级时优先组合。

---

### 3.2 接口与多态

**概念**：接口只声明“能做什么”，不关心“怎么做”；具体实现可以替换，调用方只依赖接口。

**项目对照**：

- `IRepository<TEntity>` 声明仓储能力。
- `ICrudAppService<TDto, TCreateRequest, TUpdateRequest>` 声明通用 CRUD 能力。
- `CrudViewModelBase` 只依赖接口，不依赖具体实现。

**面试常问**：

- 接口和抽象类的选择？
  - 需要共享字段、构造函数或默认实现时用抽象类；只想定义能力、支持多个不相干实现时用接口。项目里常用“接口 + 抽象基类”组合。
- “面向接口编程”带来什么好处？
  - 降低耦合、实现可替换、便于单元测试和扩展。
- 什么是里氏替换原则？
  - 子类对象应能替换父类对象而不破坏程序正确性，即子类不应改变父类约定的行为。

---

### 3.3 泛型与泛型约束

**概念**：用类型参数写出可复用的代码；`where TEntity : BaseEntity` 限制类型参数必须继承自某个基类。

**项目对照**：

- `src/WpfInventory.Infrastructure/Persistence/Repositories/Repository.cs`

```csharp
public class Repository<TEntity> : IRepository<TEntity> where TEntity : BaseEntity
```

- `src/WpfInventory.Application/Services/Crud/CrudAppService.cs` 使用四个泛型参数。

**面试常问**：

- 泛型约束有哪些种类？
  - 常见有 `class`、`struct`、`notnull`、基类约束、接口约束、`new()`、`unmanaged` 等，用于限制类型参数能做什么。
- 泛型方法 vs 泛型类？
  - 泛型类的类型参数作用于整个类型；泛型方法的类型参数只作用于该方法，调用时可独立推断。
- 装箱拆箱是什么？泛型如何避免装箱？
  - 值类型转 `object` 是装箱，`object` 转回值类型是拆箱，会分配堆对象。泛型用具体类型替换 `object`，直接操作值类型，避免装箱。

---

### 3.4 可空引用类型

**概念**：`string?` 表示该引用可能为 null，编译器会提示可能的 null 解引用风险。

**项目对照**：

- `Product.Description` 是 `string?`，表示商品描述允许为空。
- 仓储查询返回 `Task<TEntity?>`，表示查询结果可能不存在。

**面试常问**：

- 值类型的 `Nullable<T>` 和引用类型的可空标注有什么区别？
  - `Nullable<T>` 是真正的结构体包装，能区分“有值/无值”；可空引用类型只是编译期静态分析标注，运行时仍是普通引用。
- `null!`、`??`、`?.` 分别表示什么？
  - `null!` 告诉编译器这里不会为 null，抑制警告；`??` 左边为 null 时取右边；`?.` 安全导航，左边为 null 时整体返回 null。

---

### 3.5 DTO 与记录类型

**概念**：DTO 用于在层与层之间传输数据，避免把数据库实体直接暴露给 UI。

**项目对照**：

- `src/WpfInventory.Application/Dtos/Products/ProductDto.cs`
- 请求对象：`CreateProductRequest.cs`、`UpdateProductRequest.cs`

**面试常问**：

- 为什么不用实体直接绑定到界面？
  - 实体可能带导航属性、循环引用、敏感字段和数据库特性，暴露给 UI 会造成耦合、序列化和校验困难。DTO 只携带界面需要的数据。
- DTO 和实体之间用什么工具映射？AutoMapper 的原理是什么？
  - 常用 AutoMapper。它根据配置读取属性对应关系，生成对象赋值逻辑，现代版本会编译表达式树以提高性能。

---

### 3.6 扩展方法

**概念**：在不修改原类的前提下，给已有类型“追加”方法；本项目用它把一组 DI 注册封装成一个方法。

**项目对照**：

- `AddApplication(this IServiceCollection services)` 在 `src/WpfInventory.Application/DependencyInjection.cs`
- `AddInfrastructure(this IServiceCollection services, IConfiguration configuration)` 在 `src/WpfInventory.Infrastructure/DependencyInjection.cs`

**面试常问**：

- 扩展方法的本质是什么？
  - 本质是静态类里的静态方法，第一个参数加 `this`。编译后仍是普通静态方法调用，不能访问私有成员。
- 为什么 LINQ 看起来是给 `IEnumerable<T>` 加了很多方法？
  - LINQ 标准查询运算符就是定义在静态类上的扩展方法，如 `Enumerable.Where`。

---

### 3.7 partial 类与 Source Generator

**概念**：一个类可以拆分到多个文件；CommunityToolkit.Mvvm 通过源生成器自动补全属性通知和命令实现。

**项目对照**：

```csharp
public partial class CategoryViewModel : CrudViewModelBase<...>
{
    [ObservableProperty]
    private bool isEditing;
}
```

`[ObservableProperty]` 自动生成 `IsEditing` 属性和 `OnIsEditingChanged` 钩子；`[RelayCommand]` 自动生成 `LoadCommand`、`SaveCommand` 等。

**面试常问**：

- Source Generator 是什么？和反射/AOP 有什么不同？
  - 它在编译期分析代码并生成新代码进程序集，无运行时开销；反射和多数 AOP 在运行时工作，会带来一定性能成本。
- 为什么 MVVM 工具包要用代码生成，而不是运行时反射？
  - 为了获得编译期类型安全、更好的性能和可调试性，同时大幅减少样板代码。

---

### 3.8 反射

**概念**：运行时读取类型的元数据并动态调用成员。

**项目对照**：

- `CrudAppService.GetId` 用 `GetProperty("Id")` 从请求对象反射读取主键。
- `MainWindowViewModel.Navigate` 用反射调用页面的 `LoadCommand`。

**面试常问**：

- 反射的性能问题？
  - 反射比直接调用慢，因为要查找元数据、装箱、权限检查等。应避免热路径频繁反射，可缓存结果。
- 如何用表达式树替代反射提升性能？
  - 把反射访问编译成表达式树并缓存为强类型委托，之后按普通委托调用，性能接近直接访问。

---

### 3.9 委托与 Lambda

**概念**：把方法当作参数传递；`Func<Task>` 表示一个“返回 Task 的方法”。

**项目对照**：

- `CrudViewModelBase.ExecuteWriteAsync(Func<Task> action)` 把新增/修改/删除的公共流程抽象出来。
- `EfUnitOfWork.ExecuteInTransactionAsync(Func<Task> action)` 把“业务动作”传入事务。

**面试常问**：

- `Action`、`Func`、`Predicate` 的区别？
  - `Action` 无返回值；`Func` 有返回值；`Predicate<T>` 接收一个参数并返回 bool。
- Lambda 如何捕获外部变量？
  - Lambda 形成闭包，捕获的是变量本身而不是当时的副本，因此后续变量变化会反映到 lambda 内。

---

### 3.10 集合与 LINQ

**概念**：用声明式查询语法操作集合，EF Core 会把 LINQ 翻译成 SQL。

**项目对照**：

- `RoleViewModel.SelectedPermissionIds()` 中的 `Where / Select / ToList`
- `StockTransactionRepository` 中 `OrderByDescending(x => x.CreatedAt)`

**面试常问**：

- `IEnumerable<T>` 和 `IQueryable<T>` 的区别？
  - `IEnumerable<T>` 在内存中执行；`IQueryable<T>` 构建表达式树，由 provider 翻译到数据源（如 SQL），可在数据库端过滤。
- 延迟执行和立即执行？
  - `Where`、`Select` 等定义查询时不执行，遍历或调用 `ToList/First/Count` 时才执行，这就是延迟执行。
- `FirstOrDefault` 和 `SingleOrDefault` 的区别？
  - `FirstOrDefault` 返回第一个或默认值；`SingleOrDefault` 要求最多一个元素，多于一个会抛异常。

---

### 3.11 异常处理

**概念**：业务错误集中捕获，避免 UI 崩溃；`throw` 用于阻止非法状态继续执行。

**项目对照**：

- ViewModel 里 `try/catch/finally` 统一处理错误。
- `App.OnDispatcherUnhandledException` 捕获 UI 线程未处理异常。
- 应用服务用 `?? throw new KeyNotFoundException(...)` 明确报错。

**面试常问**：

- `try/catch/finally` 的执行顺序？
  - 进入 try，若抛异常则跳到匹配的 catch；无论是否异常、是否 return，finally 都会执行。
- 什么时候该捕获，什么时候该让异常向上抛？
  - 当前层能处理或需要转换为用户可读信息时捕获；无法处理时应记录或包装后向上抛，避免吞掉异常。
- 全局异常处理怎么写？
  - WPF 可用 `Application.DispatcherUnhandledException`；另外还有 `AppDomain.UnhandledException` 和 `TaskScheduler.UnobservedTaskException`。

---

### 3.12 IDisposable 与 using

**概念**：需要释放非托管/资源型对象时实现 `IDisposable`；`using` 保证作用域结束时自动释放。

**项目对照**：

- `App.OnStartup` 中 `using var scope = _host.Services.CreateScope();`
- `EfUnitOfWork` 中 `await using var transaction = ...`

**面试常问**：

- `using` 和 `await using` 的区别？
  - `using` 调用同步 `Dispose`；`await using` 用于 `IAsyncDisposable`，会 `await` 异步释放完成。
- `Dispose` 和 `Finalize` 的区别？
  - `Dispose` 是确定性、由调用方控制的释放；`Finalize` 由 GC 在对象回收前触发，不确定且代价高。
- DI 容器如何管理 `IDisposable` 的生命周期？
  - 容器创建的对象若实现 `IDisposable`，会在其所属作用域结束时自动调用 `Dispose`。

## 4. 异步与多线程

### 4.1 async / await 与 Task

**概念**：异步方法返回 `Task`，`await` 等待完成但不阻塞线程；UI 线程在等待期间仍能响应输入。

**项目对照**：几乎所有仓储、服务、ViewModel 命令方法都是 `async Task`，例如 `CrudViewModelBase.LoadAsync`、`CrudAppService.CreateAsync`。

**面试常问**：

- `async/await` 的本质是什么？它开新线程吗？
  - 本质是编译器生成状态机：`await` 挂起方法并注册回调，操作完成后继续执行，本身不会主动开新线程。
- `Task.Run` 和 `async/await` 有什么关系？
  - `Task.Run` 把工作调度到线程池执行；`async/await` 是等待异步操作完成的语法，不负责决定在哪个线程执行。
- 异步方法没有 `await` 会怎样？
  - 编译器会警告，方法同步执行完并返回一个已完成的 `Task`，异步语义不生效。

---

### 4.2 async void

**概念**：`async void` 无法被调用方等待，异常处理规则特殊，通常只用于事件处理器。

**项目对照**：`src/WpfInventory.App/App.xaml.cs` 的 `protected override async void OnStartup(...)`。

**面试常问**：

- 为什么说 `async void` 危险？
  - 调用方无法 `await` 它，异常会直接抛到调用上下文，难以捕获；除了事件处理器，应避免使用。
- WPF 事件处理器为什么常写 `async void`？
  - 事件签名要求 `void`，又要执行异步操作，只能写 `async void`；但方法内部必须自己 `try/catch` 处理异常。

---

### 4.3 CancellationToken

**概念**：在用户取消或超时时，把取消信号传递给正在执行的异步操作。

**项目对照**：仓储和服务方法普遍带 `CancellationToken cancellationToken = default`，例如 `IRepository<TEntity>.GetAllAsync`。

**面试常问**：

- 取消机制如何传播？
  - 把同一个 `CancellationToken` 层层传给支持取消的 API，被取消时内部抛 `OperationCanceledException` 或提前返回。
- 实际项目里从哪里创建 `CancellationTokenSource`？
  - 由发起方创建 `CancellationTokenSource`，把 `.Token` 传入方法；需要取消时调用 `.Cancel()`，并在完成后 `Dispose`。

---

### 4.4 await using 与异步资源释放

**概念**：等待异步释放完成，常用于数据库事务、流等资源。

**项目对照**：`src/WpfInventory.Infrastructure/Persistence/EfUnitOfWork.cs`

```csharp
await using var transaction = await _dbContext.Database.BeginTransactionAsync(cancellationToken);
```

**面试常问**：

- 异步释放为什么需要 `await`？
  - 某些资源的释放涉及异步 IO，需要等待其完成，`DisposeAsync` 返回可等待对象。
- 什么是 IAsyncDisposable？
  - `IDisposable` 的异步版本，定义 `DisposeAsync()`，配合 `await using` 使用。

---

### 4.5 UI 线程与 Dispatcher

**概念**：WPF 是单线程 UI 模型，控件只能在创建它的 UI 线程修改；`Dispatcher` 负责把操作投递回 UI 线程。

**项目对照**：

- `App.xaml.cs` 使用 `DispatcherUnhandledException` 捕获 UI 线程异常。
- MVVM 命令默认在 UI 上下文执行，保证属性更新回到 UI 线程。

**面试常问**：

- WPF 为什么是单线程 UI 模型？
  - UI 对象有线程亲和性，多线程直接操作控件极易竞态；单线程模型简化了界面一致性和线程安全问题。
- 后台线程更新 UI 会怎样？如何正确切换线程？
  - 会抛异常。应使用 `Dispatcher.Invoke/BeginInvoke`，或让 `async/await` 捕获 UI 上下文，在 UI 线程继续执行。

---

### 4.6 当前尚未覆盖的并发知识点

本项目目前没有：`Task.Run`、`Parallel`、`lock`、`SemaphoreSlim`、`ConcurrentDictionary`、`Channel`。

这些对应“多线程/并发”面试题，建议后续用“并发扣库存”模块补齐。

## 5. 设计模式与架构思想

| 模式/思想 | 项目位置 | 说明 |
| --- | --- | --- |
| 分层架构 / 洋葱架构雏形 | 四个项目按职责分层 | 依赖向内，核心不依赖基础设施 |
| 依赖注入 / 控制反转 IoC | `App.xaml.cs`、各 `DependencyInjection.cs` | 由容器创建对象、注入依赖 |
| 依赖倒置原则 DIP | `Domain/Repositories/*` 接口 | 高层依赖抽象，不依赖具体实现 |
| 仓储模式 Repository | `IRepository<T>`、`Repository<T>` | 把数据访问封装成集合语义 |
| 工作单元 UnitOfWork | `IUnitOfWork`、`EfUnitOfWork` | 统一提交和事务控制 |
| 模板方法模式 | `CrudViewModelBase<TDto, ...>` | 基类定义流程骨架，子类填充具体步骤 |
| 泛型 CRUD 复用 | `CrudAppService<TEntity, ...>` | 用泛型消除重复增删改查代码 |
| 组合根 Composition Root | `App.ConfigureServices` | 唯一集中配置依赖的地方 |
| DTO 模式 | `Application/Dtos` | 层间传输，不暴露实体 |
| 校验器模式 | `Application/Validators` | 用 FluentValidation 分离校验规则 |

**面试常问**：

- 仓储模式和 EF Core 的 `DbSet` 有什么区别？
  - `DbSet` 是 EF 基础设施，直接暴露数据库能力；仓储是抽象层，隔离 EF 细节，便于替换实现、集中查询和测试。
- UnitOfWork 解决了什么问题？
  - 协调多个仓储/聚合的写入，统一提交和事务，保证业务一致性。
- 模板方法模式和方法重写、策略模式有什么不同？
  - 模板方法在基类固定流程骨架，子类实现可变步骤，用继承；策略模式把算法封装为可替换对象，用组合。
- AutoMapper 是反射实现吗？性能敏感场景要注意什么？
  - 传统版本大量依赖反射，性能敏感时要做映射配置验证；新版会生成表达式/编译代码，也可换 Mapster 等高性能方案。

## 6. EF Core 与数据库

### 6.1 DbContext 与 DbSet

**概念**：`DbContext` 是数据库会话，`DbSet<T>` 代表一张表。

**项目对照**：`src/WpfInventory.Infrastructure/Data/AppDbContext.cs`

**面试常问**：

- DbContext 的生命周期应该怎么设置？
  - 通常与业务请求/页面作用域一致，注册为 Scoped，短生命周期，避免长期追踪大量实体。
- 为什么 DbContext 不是线程安全的？
  - 内部维护变更跟踪器等状态，并发使用会数据竞态，应每个线程/作用域独立实例。

---

### 6.2 Fluent API 配置

**概念**：用代码配置表名、主键、字段长度、默认值、关系，而不是把约束散落在实体上。

**项目对照**：`src/WpfInventory.Infrastructure/Data/Configurations/ProductConfiguration.cs`

```csharp
builder.Property(x => x.Sku).IsRequired().HasMaxLength(50);
builder.HasIndex(x => x.Sku).IsUnique();
builder.Property(x => x.UnitPrice).HasPrecision(18, 2);
builder.HasOne(x => x.Category).WithMany(x => x.Products)
       .HasForeignKey(x => x.CategoryId)
       .OnDelete(DeleteBehavior.Restrict);
```

**面试常问**：

- Data Annotation 和 Fluent API 怎么选？
  - 简单字段可用注解；复杂关系、约束集中管理时用 Fluent API。建议项目统一使用 Fluent API，实体更干净。
- `HasPrecision` 为什么重要？
  - 指定小数精度和位数，避免数据库默认精度导致金额等数据舍入错误。
- 唯一索引和外键约束如何配置？
  - 唯一索引用 `HasIndex(...).IsUnique()`；外键用 `HasOne(...).WithMany(...).HasForeignKey(...)`。

---

### 6.3 关系映射

**概念**：实体间的一对多、多对多用导航属性和外键表达。

**项目对照**：

- `Category.Products` 与 `Product.CategoryId`：一对多。
- `UserRole`、`RolePermission`：多对多中间表。

**面试常问**：

- 一对多、多对多如何映射？
  - 一对多用“一方的集合导航 + 多方外键”；多对多通过中间实体表达两边的一对多。
- `Include / ThenInclude` 解决什么问题？N+1 查询是什么？
  - `Include` 预加载导航属性，避免延迟加载产生大量查询；N+1 指先查主表一条，再为每条导航数据单独查一次子表。

---

### 6.4 迁移

**概念**：用代码记录数据库结构变化，可重复应用。

**项目对照**：`src/WpfInventory.Infrastructure/Data/Migrations`

**面试常问**：

- `Add-Migration`、`Update-Database` 做了什么？
  - `Add-Migration` 根据模型变化生成迁移代码和快照；`Update-Database` 把未应用的迁移执行到目标数据库。
- 迁移如何和团队协作/生产环境配合？
  - 迁移文件纳入版本控制，合并时避免冲突；发布时用 `migrate` 命令或启动初始化自动应用迁移。

---

### 6.5 查询优化

**概念**：只读查询用 `AsNoTracking`；需要导航属性时用 `Include`。

**项目对照**：`Repository<TEntity>.GetAllAsync` 使用 `AsNoTracking().ToListAsync`；`UserRepository` 使用多层 `ThenInclude`。

**面试常问**：

- 跟踪查询和 AsNoTracking 的区别？
  - 跟踪查询保存实体快照用于更新检测，内存开销更大；`AsNoTracking` 不跟踪，只读场景更快、更省内存。
- EF Core 何时生成 SQL？延迟执行体现在哪里？
  - 构建 `IQueryable` 时只生成表达式树，遍历或调用 `ToList/First/Count` 等终结操作时才翻译并执行 SQL。

---

### 6.6 事务

**概念**：多个写操作要么全部成功，要么全部回滚。

**项目对照**：`EfUnitOfWork.ExecuteInTransactionAsync`

**面试常问**：

- 事务的 ACID 是什么？
  - 原子性、一致性、隔离性、持久性。
- 悲观锁、乐观并发、死锁分别是什么？
  - 悲观锁先锁定资源再操作；乐观并发靠版本号/并发令牌在提交时检测冲突；死锁是两个事务互相等待对方持有的资源。
- EF Core 的并发冲突如何检测？
  - 配置并发令牌（ConcurrencyToken），提交时检测版本变化，冲突抛 `DbUpdateConcurrencyException`。

## 7. WPF / MVVM

### 7.1 数据绑定

**概念**：View 通过 `Binding` 和 ViewModel 属性双向同步。

**项目对照**：

```xml
<TextBox Text="{Binding Name, UpdateSourceTrigger=PropertyChanged}" />
<DataGrid ItemsSource="{Binding Items}" SelectedItem="{Binding SelectedItem}" />
```

**面试常问**：

- 绑定模式有哪些？
  - `OneWay`、`TwoWay`、`OneTime`、`OneWayToSource`。
- `UpdateSourceTrigger` 什么时候用？
  - 默认 `TextBox.Text` 是 `LostFocus`；需要输入即时更新时用 `PropertyChanged`。
- 绑定失败怎么排查？
  - 查看 Visual Studio 输出窗口的绑定错误，检查 `DataContext`、属性名和绑定路径。

---

### 7.2 INotifyPropertyChanged 与 ObservableObject

**概念**：属性变化时通知界面刷新。

**项目对照**：所有 ViewModel 继承 `ObservableObject`，用 `[ObservableProperty]` 自动生成通知代码。

**面试常问**：

- 为什么要实现 `INotifyPropertyChanged`？
  - 绑定系统依赖该事件感知属性变化，否则界面不会自动刷新。
- 手写属性和 `[ObservableProperty]` 生成结果有何不同？
  - 功能等价，都是触发属性变更；后者由源生成器生成，减少样板，且提供 `OnXxxChanged` 钩子。

---

### 7.3 ICommand 与 RelayCommand

**概念**：把按钮点击动作封装成命令，实现 View 和业务逻辑解耦。

**项目对照**：

- `[RelayCommand] private async Task LoadAsync()` 生成 `LoadCommand`。
- XAML 中 `Command="{Binding SaveCommand}"`。

**面试常问**：

- ICommand 的 `Execute` 和 `CanExecute` 是什么？
  - `Execute` 执行命令动作；`CanExecute` 决定命令当前是否可执行，返回 false 时按钮自动禁用。
- 命令和事件处理有什么区别？
  - 命令支持 `CanExecute`、可绑定、可测试、更符合 MVVM；事件处理常写在 code-behind，耦合 View。

---

### 7.4 ObservableCollection

**概念**：集合增删改时自动通知 UI 更新列表。

**项目对照**：`CrudViewModelBase.Items`、`MainWindowViewModel.NavigationItems`。

**面试常问**：

- `ObservableCollection` 和 `List<T>` 有什么区别？
  - 前者实现 `INotifyCollectionChanged`，增删改自动刷新 UI；后者不会通知界面。
- 大量数据更新时如何提升性能？
  - 批量替换整个集合、暂停通知、使用虚拟化、分页或后台加载，避免逐条插入。

---

### 7.5 导航与页面切换

**概念**：主窗口维护菜单和当前 ViewModel，点击菜单时切换右侧内容区。

**项目对照**：

- `MainWindowViewModel.SelectedItem` → `OnSelectedItemChanged` → `Navigate(...)`
- View 层用 `ContentControl` + `DataTemplate` 按 ViewModel 类型显示对应 View。

**面试常问**：

- MVVM 下如何做页面导航？
  - 维护“当前 ViewModel”属性，切换时替换它，View 通过 `DataTemplate` 自动显示对应控件。
- `DataTemplate` 如何按 ViewModel 映射 View？
  - 模板设置 `DataType="{x:Type vm:ProductViewModel}"`，绑定到该类型对象时 WPF 自动选取模板。

### 7.6 登录与窗口生命周期

**概念**：登录成功后先显示主窗口再关闭登录窗口，避免最后一个窗口关闭导致应用退出。

**项目对照**：`App.OnLoginSucceeded` 中先 `mainWindow.Show()`，再 `_loginWindow?.Close()`。

**面试常问**：

- WPF 的 `ShutdownMode` 有哪些？
  - `OnLastWindowClose`、`OnMainWindowClose`、`OnExplicitShutdown`，控制应用何时退出。
- 登录跳转主窗口的常见问题是什么？
  - 先关登录窗口会触发“最后窗口关闭”导致应用退出；应先显示主窗口，再关闭登录窗口。

## 9. 面试自查清单（含答案）

1. 为什么分层？各层放什么？
   - 让职责单一、依赖方向清晰、便于替换和测试。表现层管 UI，应用层管用例编排，领域层放实体/规则/接口，基础设施层提供数据库等实现。
2. 依赖倒置和依赖注入的区别？
   - DIP 是“依赖抽象”的设计原则，DI 是用容器注入具体实现的手段。
3. 抽象类和接口怎么选？
   - 共享状态、构造函数或默认实现用抽象类；只定义能力、多实现用接口。
4. 泛型和泛型约束是什么？
   - 泛型用类型参数复用代码；约束限制类型参数必须满足的条件，如基类、接口、`new()`。
5. `IEnumerable<T>` 和 `IQueryable<T>` 的区别？
   - 前者在内存执行；后者构建表达式树，可翻译为 SQL 在数据库端执行。
6. `async/await` 会开新线程吗？
   - 不会，编译器生成状态机，`await` 挂起并注册回调，不阻塞当前线程。
7. `async void` 为什么危险？
   - 无法被等待，异常难以捕获，只应出现在事件处理器中。
8. `CancellationToken` 如何传递？
   - 创建 `CancellationTokenSource`，把 `.Token` 层层传给异步 API，取消时抛 `OperationCanceledException`。
9. WPF 为什么是单线程 UI 模型？
   - 控件有线程亲和性，单线程避免并发访问 UI 对象，简化一致性和线程安全。
10. `INotifyPropertyChanged` 的作用？
    - 属性变化时通知绑定系统刷新界面。
11. `ICommand` 的 `CanExecute` 怎么用？
    - 返回 bool 表示命令能否执行，false 时绑定按钮自动禁用。
12. `ObservableCollection` 为什么能自动更新 UI？
    - 实现 `INotifyCollectionChanged`，集合增删改时通知绑定控件。
13. `DataContext` 是什么？绑定如何查找源？
    - 它是绑定的数据上下文；绑定从目标控件的 `DataContext` 沿视觉树向上查找，直到找到匹配属性。
14. 仓储模式解决了什么问题？
    - 隔离数据访问细节，统一查询入口，便于替换实现和单元测试。
15. UnitOfWork 解决了什么问题？
    - 协调多个仓储的写入，统一提交和事务，保证业务一致性。
16. 模板方法模式在本项目哪里体现？
    - `CrudViewModelBase` 固定“加载/新增/修改/删除”流程，子类实现表单字段和请求组装。
17. `DbContext` 为什么不是线程安全的？
    - 内部有变更跟踪器等状态，并发使用会竞态，应每个作用域独立实例。
18. `AsNoTracking` 有什么用？
    - 只读查询不跟踪实体，减少内存和开销，提升性能。
19. `Include/ThenInclude` 解决什么问题？
    - 预加载导航属性，避免 N+1 查询。
20. EF Core 事务怎么用？ACID 是什么？
    - `BeginTransactionAsync` + 提交/回滚；ACID 是原子性、一致性、隔离性、持久性。
21. 唯一索引、外键、`HasPrecision` 如何配置？
    - Fluent API 中 `HasIndex().IsUnique()`、`HasOne().HasForeignKey()`、`HasPrecision(18,2)`。
22. DI 生命周期 Singleton/Scoped/Transient 的区别？
    - Singleton 全应用一个实例；Scoped 每个作用域一个；Transient 每次解析都新建。
23. `using` 和 `await using` 的区别？
    - 分别对应 `IDisposable` 和 `IAsyncDisposable`，后者等待异步释放完成。
24. `IDisposable` 和 DI 容器如何配合？
    - 容器创建的对象若实现 `IDisposable`，作用域结束时自动释放。
25. 反射的性能问题？如何优化？
    - 反射慢，可缓存结果、用表达式树编译成委托减少热路径开销。
26. AutoMapper 的原理和使用场景？
    - 根据映射配置生成对象赋值逻辑；用于实体与 DTO 之间的层间转换。
27. FluentValidation 如何做参数校验？
    - 定义 `AbstractValidator<T>` 规则，调用 `ValidateAndThrowAsync` 在进入业务逻辑前校验。
28. 全局异常处理怎么写？
    - WPF 用 `DispatcherUnhandledException`，配合 `AppDomain.UnhandledException` 和未观察任务异常处理。
29. 如何让 ViewModel 可单元测试？
    - 通过接口注入服务依赖，ViewModel 不直接 new 具体实现，测试时注入 mock。
30. 本项目还没有覆盖哪些并发知识点？
    - `Task.Run`、`Parallel`、`lock`、`SemaphoreSlim`、并发集合、`Channel`、乐观/悲观并发控制。
